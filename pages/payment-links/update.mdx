title: 'Atualizar link de pagamento'
description: 'Atualiza dados, ativação, cupons, trial e valor do link'
sidebarTitle: 'Atualizar'

Atualização parcial: campos omitidos permanecem. `null` limpa `description`, `checkoutLayout`, `successUrl` e `cancelUrl`. Para alterar itens e bumps use as rotas de [itens](./add-item) e [bumps](./add-bump). Em um link `fixed_amount`, altere o valor com `amount`.

Permissão: `payment_link.write` (chave secreta).

## Endpoint

<CodeGroup>
```bash cURL
curl -X PATCH https://api.upag.dev/v1/payment-links/d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70 \
  -H "Authorization: Bearer sk_test_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "couponEnabled": true,
    "subscriptionData": {
      "trial": { "interval": "day", "intervalCount": 14 }
    }
  }'
```

```javascript Node.js SDK
import { Upag } from 'upag';

const upag = new Upag('sk_test_your_api_key');

const link = await upag.paymentLinks.update('d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70', {
  couponEnabled: true,
  subscriptionData: { trial: { interval: 'day', intervalCount: 14 } }, // trial: null remove o trial
});
```
</CodeGroup>

<Note>
  Em produção use `https://api.upag.io/v1` com `sk_live_...`.
</Note>

## Parâmetros

<ParamField path="paymentLinkId" type="string (uuid)" required>
  ID do link de pagamento.
</ParamField>

<ParamField body="name" type="string">
  1 a 255 caracteres.
</ParamField>

<ParamField body="description" type="string | null">
  Descrição.
</ParamField>

<ParamField body="checkoutLayout" type="string (uuid) | null">
  ID de um [layout de checkout](../checkout-layouts/reference) da conta.
</ParamField>

<ParamField body="paymentMethods" type="string[]">
  `pix` e/ou `card` (mínimo 1).
</ParamField>

<ParamField body="billingAddressCollection" type="string">
  `auto`, `required` ou `none`.
</ParamField>

<ParamField body="successUrl" type="string (url) | null">
  URL de sucesso.
</ParamField>

<ParamField body="cancelUrl" type="string (url) | null">
  URL de cancelamento.
</ParamField>

<ParamField body="active" type="boolean">
  Ativa ou desativa o link.
</ParamField>

<ParamField body="couponEnabled" type="boolean">
  Permite o comprador aplicar cupons.
</ParamField>

<ParamField body="subscriptionData" type="object">
  `trial` (`{ interval, intervalCount }` ou `null` para remover) e/ou `trialSettings.endBehavior.missingPaymentMethod` (`create_invoice` ou `cancel`). Campos omitidos mantêm o valor atual.
</ParamField>

<ParamField body="paymentMethodCollection" type="string">
  `always` ou `if_required`.
</ParamField>

<ParamField body="amount" type="integer">
  Só em links `fixed_amount`: novo valor em centavos, de `500` (R$ 5,00) a `2147483647`. Vale para as próximas sessões; uma sessão já aberta mantém o valor com que começou.
</ParamField>

<ParamField body="type" type="string">
  Opcional; se enviado, deve ser o tipo atual do link (o tipo não muda).
</ParamField>

Em um link `fixed_amount`, `couponEnabled: true` e trial em `subscriptionData` são recusados. Quando `amount` ou `paymentMethods` mudam, o valor é validado de novo contra cada método.

- `404` — `PAYMENT_LINK_NOT_FOUND` ou `CHECKOUT_LAYOUT_NOT_FOUND`.
- `400` — alterações de trial ou métodos que violem as [regras de consistência](./reference); `PAYMENT_LINK_TYPE_MISMATCH` (`type` diferente do atual, `amount` em link `product`, cupom ou trial em link `fixed_amount`); `ACCOUNT_PAYMENT_METHOD_DISABLED` em link `fixed_amount`.
- `422` — validação do corpo; `PAYMENT_METHOD_AMOUNT_TOO_LOW` / `PAYMENT_METHOD_AMOUNT_TOO_HIGH` se o valor de um link `fixed_amount` ficar fora dos limites de um método.
