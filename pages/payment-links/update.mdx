Atualização parcial: campos omitidos permanecem. `null` limpa `description`, `checkoutLayout`, `successUrl` e `cancelUrl`. Para alterar itens e bumps use as rotas de [itens](./add-item) e [bumps](./add-bump).

O tipo do link não muda. Num link `fixed_amount`, `couponEnabled: true`, um `trial` ou um `maxCycles` são recusados; num link `product`, `amount` é recusado. Os dois casos retornam `400 PAYMENT_LINK_TYPE_MISMATCH`.

Permissão: `payment_link.write` (chave secreta).

## Endpoint

<CodeGroup>
```bash cURL
curl -X PATCH https://api.upag.io/v1/payment-links/d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70 \
  -H "Authorization: Bearer sk_live_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "couponEnabled": true,
    "subscriptionData": {
      "trial": { "interval": "day", "intervalCount": 14 }
    }
  }'
```

```javascript Node.js SDK
import { Upag } from 'upag';

const upag = new Upag('sk_live_your_api_key');

const link = await upag.paymentLinks.update('d4e5f6a7-b8c9-4d0e-9f1a-2b3c4d5e6f70', {
  couponEnabled: true,
  subscriptionData: { trial: { interval: 'day', intervalCount: 14 } }, // trial: null remove o trial
});
```
</CodeGroup>

<Note>
  Os exemplos usam produção (`https://api.upag.io/v1`) com `sk_live_…`. Para testar, use o sandbox (`https://api.upag.dev/v1`) com `sk_test_…`.
</Note>

## Parâmetros

<ParamField path="paymentLinkId" type="string (uuid)" required>
  ID do link de pagamento.
</ParamField>

<ParamField body="name" type="string">
  1 a 255 caracteres.
</ParamField>

<ParamField body="description" type="string | null">
  Descrição.
</ParamField>

<ParamField body="checkoutLayout" type="string (uuid) | null">
  ID de um [layout de checkout](../checkout-layouts/reference) da conta.
</ParamField>

<ParamField body="paymentMethods" type="string[]">
  `pix`, `card` e/ou `boleto` (mínimo 1). Num link `fixed_amount`, cada forma precisa estar ativa na conta e aceitar o `amount` atual.
</ParamField>

<ParamField body="billingAddressCollection" type="string">
  `auto`, `required` ou `none`.
</ParamField>

<ParamField body="successUrl" type="string (url) | null">
  URL de sucesso.
</ParamField>

<ParamField body="cancelUrl" type="string (url) | null">
  URL de cancelamento.
</ParamField>

<ParamField body="active" type="boolean">
  Ativa ou desativa o link.
</ParamField>

<ParamField body="couponEnabled" type="boolean">
  Permite o comprador aplicar cupons. Só em links `product`.
</ParamField>

<ParamField body="amount" type="integer">
  Só em links `fixed_amount`. Novo valor, em centavos, de `500` a `2147483647`.
</ParamField>

<ParamField body="type" type="string">
  Aceito apenas se for igual ao tipo atual do link (`product` ou `fixed_amount`); outro valor retorna `PAYMENT_LINK_TYPE_MISMATCH`.
</ParamField>

<ParamField body="subscriptionData" type="object">
  `trial` (`{ interval, intervalCount }` ou `null` para remover), `trialSettings.endBehavior.missingPaymentMethod` (`create_invoice` ou `cancel`) e/ou `maxCycles` (inteiro ≥ 1, ou `null` para remover o limite). Campos omitidos mantêm o valor atual. Vale para as compras iniciadas depois da alteração.
</ParamField>

<ParamField body="paymentMethodCollection" type="string">
  `always` ou `if_required`.
</ParamField>

## Erros

- `404` — `PAYMENT_LINK_NOT_FOUND` ou `CHECKOUT_LAYOUT_NOT_FOUND`.
- `400` — `PAYMENT_LINK_TYPE_MISMATCH`: mudança de `type`, `amount` num link `product`, ou `couponEnabled: true`, `trial` ou `maxCycles` num link `fixed_amount`.
- `400` — alterações de trial ou métodos que violem as [regras de consistência](./reference).
- `400` — `ACCOUNT_PAYMENT_METHOD_DISABLED`: num link `fixed_amount`, uma das `paymentMethods` está desativada na conta.
- `422` — `PAYMENT_METHOD_AMOUNT_TOO_LOW` ou `PAYMENT_METHOD_AMOUNT_TOO_HIGH`: num link `fixed_amount`, o `amount` fica fora dos limites de valor de uma das `paymentMethods`.
- `422` — validação do corpo.
