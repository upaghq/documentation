Resolve a sessão de checkout pelo código que fica no fim da `url` dela (`https://checkout.upag.io/cs/<code>`). É assim que a página hospedada abre uma sessão criada no servidor ([Criar](./create)), pelo [Shopify](./shopify) ou reaberta depois de recarregar a página.

**Não há autenticação**: o código é a credencial, então trate a `url` da sessão como um link de pagamento. Cada chamada numa sessão aberta emite um `clientSecret` **novo** e invalida o anterior, porque só o hash dele é guardado. Use o `clientSecret` devolvido como `Authorization: Bearer <clientSecret>` para [obter](./retrieve), [confirmar](./confirm) e mexer em [cupom](./apply-coupon) daquela sessão.

Limite: 30 requisições por minuto por IP. Excedido, a API responde `429`.

<Note>
  Os exemplos usam o sandbox (`https://api.upag.dev/v1`). Em produção use `https://api.upag.io/v1`; no navegador, o `upag-js` usa só a chave pública (`pk_test_…` / `pk_live_…`) e escolhe o host por ela.
</Note>

## Endpoint

<CodeGroup>
```bash cURL
curl https://api.upag.dev/v1/checkout/sessions/code/Hq7Kd2xPzR4tWm9b
```

```javascript upag-js
import { UpagJs } from 'upag-js';

const upag = new UpagJs('pk_test_your_public_key');

const code = window.location.pathname.split('/cs/')[1];
const session = await upag.checkout.retrieveByCode(code);

if (session.status === 'open') {
  const { id, clientSecret } = session;
  // monte a página e confirme com clientSecret
} else if (session.successUrl) {
  window.location.href = session.successUrl;
}
```
</CodeGroup>

## Parâmetros

<ParamField path="code" type="string" required>
  Código da sessão, o trecho depois de `/cs/` na `url` (até 64 caracteres).
</ParamField>

## Erros

| Status | Código | Quando |
| ------ | ------ | ------ |
| `404` | `CHECKOUT_SESSION_NOT_FOUND` | Nenhuma sessão com esse código (a resposta é a mesma para qualquer código desconhecido) |
| `422` | `VALIDATION_FAILED` | `code` com mais de 64 caracteres |
| `429` | n/a | Mais de 30 requisições por minuto pelo mesmo IP |
