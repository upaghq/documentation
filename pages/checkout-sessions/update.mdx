Altera uma sessão `open`. Os campos omitidos mantêm o valor; `null` limpa o cliente ou uma URL. Itens, bumps e teste não mudam: para isso, [crie outra sessão](./create).

Permissão: `checkout_session.write`. Apenas chave secreta (`sk_…`).

<Note>
  Os exemplos usam o sandbox (`https://api.upag.dev/v1`). Em produção use `https://api.upag.io/v1` com `sk_live_…`.
</Note>

## Endpoint

<CodeGroup>
```bash cURL
curl -X PATCH https://api.upag.dev/v1/checkout/sessions/4f9d2b71-6c03-4e58-9a1d-8b3e7c0f5a26 \
  -H "Authorization: Bearer sk_test_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "paymentMethods": ["card"],
    "successUrl": "https://exemplo.com.br/pedido/concluido"
  }'
```

```javascript Node.js SDK
import { Upag } from 'upag';

const upag = new Upag('sk_test_your_api_key');

const session = await upag.checkoutSessions.update('4f9d2b71-6c03-4e58-9a1d-8b3e7c0f5a26', {
  paymentMethods: ['card'],
  successUrl: 'https://exemplo.com.br/pedido/concluido',
});
```
</CodeGroup>

## Parâmetros

<ParamField path="sessionId" type="string (uuid)" required>
  ID da sessão.
</ParamField>

<ParamField body="customer" type="string (uuid) | null">
  UUID de um [cliente](../customers/reference) da conta, ou `null` para desassociar.
</ParamField>

<ParamField body="paymentMethods" type="array">
  `pix` e/ou `card`, mínimo 1. Numa sessão com teste e `paymentMethodCollection: "always"`, `card` precisa continuar na lista.
</ParamField>

<ParamField body="successUrl" type="string (url) | null">
  URL de retorno depois do pagamento. `null` remove.
</ParamField>

<ParamField body="cancelUrl" type="string (url) | null">
  URL de retorno se o pagador desistir. `null` remove.
</ParamField>

## Erros

| Status | Código | Quando |
| ------ | ------ | ------ |
| `404` | `CHECKOUT_SESSION_NOT_FOUND` | A sessão não existe ou é de outra conta |
| `404` | `CUSTOMER_NOT_FOUND` | O cliente não existe na conta |
| `409` | `CHECKOUT_SESSION_NOT_OPEN` | A sessão já está `complete` ou `expired` |
| `400` | `CHECKOUT_SESSION_TRIAL_REQUIRES_CARD` | A sessão tem teste com `paymentMethodCollection: "always"` e `card` ficaria fora de `paymentMethods` |
| `422` | `VALIDATION_FAILED` | `paymentMethods` vazio ou URL inválida |
