Paga a sessão. Na primeira chamada a Upag resolve o pagador, cria a **fatura** (e a **assinatura**, se houver itens recorrentes) e cobra. As chamadas seguintes pagam a mesma fatura: é assim que se tenta de novo depois de um cartão recusado, ou se troca entre Pix e cartão.

- **Cartão**: a resposta já traz o resultado. Aprovado, a sessão fica `complete`; recusado, continua `open` e dá para tentar de novo.
- **Pix**: a sessão fica `open` com o QR code na cobrança, e vira `complete` quando o pagamento é confirmado. Acompanhe por [webhook](../webhooks/payload-checkout).
- **Nada a pagar hoje** (um teste cobre todos os itens): não há cobrança nem fatura. A assinatura nasce `trialing` e a sessão fica `complete` na hora. Envie `paymentMethod` em vez de `charge`. Veja [Teste grátis](../guides/free-trial).

Dois chamadores podem confirmar, com a mesma rota e respostas diferentes:

| Quem | Credencial | Cliente (`customer`) | Resposta |
| ---- | ---------- | -------------------- | -------- |
| Seu servidor | Chave secreta `sk_…` | UUID de um cliente, ou os dados dele | Sessão completa, com `customer`, `charge` e `invoice` expandidos |
| Navegador do pagador | `clientSecret` | Só os dados do pagador | [Visão do pagador](./retrieve) |

Permissão: `checkout_session.write`.

<Note>
  Os exemplos usam o sandbox (`https://api.upag.dev/v1`). Em produção use `https://api.upag.io/v1` com `sk_live_…`; no navegador, o `upag-js` usa só a chave pública.
</Note>

## Do servidor

<CodeGroup>
```bash cURL
curl -X POST https://api.upag.dev/v1/checkout/sessions/4f9d2b71-6c03-4e58-9a1d-8b3e7c0f5a26/confirm \
  -H "Authorization: Bearer sk_test_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "customer": {
      "name": "Maria Pagadora",
      "email": "maria@example.com",
      "document": { "type": "cpf", "number": "39053344705" }
    },
    "charge": { "method": "pix" }
  }'
```

```javascript Node.js SDK
import { Upag } from 'upag';

const upag = new Upag('sk_test_your_api_key');

const result = await upag.checkoutSessions.confirm('4f9d2b71-6c03-4e58-9a1d-8b3e7c0f5a26', {
  customer: {
    name: 'Maria Pagadora',
    email: 'maria@example.com',
    document: { type: 'cpf', number: '39053344705' },
  },
  charge: { method: 'pix' },
});

// result.charge.pix.copyPaste: copia e cola do Pix
// result.charge.pix.qrCodeUrl: imagem PNG do QR code
```
</CodeGroup>

Tokenize o cartão antes ([Criar cartão](../cards/create)) e envie o `id`. Com 3D Secure, abra antes a [sessão 3DS da sessão de checkout](./three-d-secure) e envie o ID dela em `threeDSecureSession`.

  -H "Content-Type: application/json" \

## Do navegador

Com o `clientSecret` de [Iniciar sessão](./start). Os cartões são tokenizados no navegador com `upag.cards.create`, usando a chave pública.

<CodeGroup>
```bash cURL
curl -X POST https://api.upag.dev/v1/checkout/sessions/4f9d2b71-6c03-4e58-9a1d-8b3e7c0f5a26/confirm \
  -H "Authorization: Bearer Zk3v0pQ8xJ2mR7cYt1LwN5dHs9uAeB4gXo6iFqVjT0E" \
  -H "Content-Type: application/json" \
  -d '{
    "customer": {
      "name": "Maria Pagadora",
      "email": "maria@example.com",
      "document": { "type": "cpf", "number": "39053344705" }
    },
    "charge": { "method": "pix" }
  }'
```

```javascript upag-js
import { UpagJs } from 'upag-js';

const upag = new UpagJs('pk_test_your_public_key');

const paid = await upag.checkout.confirm(id, clientSecret, {
  customer: {
    name: 'Maria Pagadora',
    email: 'maria@example.com',
    document: { type: 'cpf', number: '39053344705' },
  },
  charge: { method: 'pix' },
});

// paid.charge.pix.copyPaste: copia e cola do Pix
```
</CodeGroup>

Cartão, no navegador:

```javascript upag-js
const card = await upag.cards.create({
  number: '4242424242424242',
  expirationMonth: 12,
  expirationYear: 2030,
  cvv: '123',
  holderName: 'Maria Pagadora',
});

const paid = await upag.checkout.confirm(id, clientSecret, {
  customer: {
    name: 'Maria Pagadora',
    document: { type: 'cpf', number: '39053344705' },
  },
  charge: { method: 'card', card: card.id, installments: 1 },
});

if (paid.status === 'complete') {
  // aprovado
} else if (paid.charge?.error) {
  // recusado: mostre paid.charge.error.message e deixe tentar de novo
}
```

Num teste sem nada a pagar hoje (`session.trial` presente e `session.amount === 0`), envie `paymentMethod` em vez de `charge`:

```javascript upag-js
await upag.checkout.confirm(id, clientSecret, {
  customer: {
    name: 'Maria Pagadora',
    document: { type: 'cpf', number: '39053344705' },
  },
  paymentMethod: { type: 'card', card: card.id },
});
```

O navegador é limitado a 10 confirmações por minuto por sessão e por IP, e não aceita um UUID em `customer`.

## Parâmetros

<ParamField path="sessionId" type="string (uuid)" required>
  ID da sessão.
</ParamField>

<ParamField body="customer" type="string (uuid) | object" required>
  O pagador. Do servidor: UUID de um [cliente](../customers/reference) da conta, ou os dados do pagador (a Upag acha o cliente pelo documento ou cria um, e atualiza o nome, e-mail, telefone e endereço enviados). Do navegador: **só os dados**.

  - `name` (obrigatório): nome.
  - `document` (obrigatório, exceto quando a sessão já tem um cliente com documento): `{ type: "cpf" | "cnpj", number }`.
  - `email`: opcional.
  - `phone`: opcional, `{ countryCode, areaCode, number }`.
  - `address`: opcional, com `street`, `number`, `complement`, `neighborhood`, `city`, `state`, `country` e `zip`.

  Se a sessão já pertence a um cliente (criada com `customer` ou por uma tentativa anterior), outro cliente é recusado.

  Se esse cliente foi criado **sem documento**, o pagador precisa informar o `document`: ele é gravado no cliente da sessão (uma única vez) e é esse cliente que paga, mesmo que outro cliente da conta já tenha o mesmo documento. Se o cliente já tem documento, o `document` enviado precisa ser o dele.
</ParamField>

<ParamField body="bumps" type="array" default="[]">
  UUIDs dos `bumps` da sessão que o pagador aceitou. Só valem na primeira tentativa.
</ParamField>

<ParamField body="charge" type="object">
  Como pagar. Obrigatório quando há valor a pagar hoje; proibido quando não há. Não pode vir junto de `paymentMethod`.

  - `method` (obrigatório): `pix` ou `card`. Precisa estar em `paymentMethods` da sessão.
  - **Pix**: `dueDate` (ISO 8601, opcional): vencimento do QR code.
  - **Cartão**: `card` (obrigatório, UUID de um [cartão tokenizado](../cards/create)), `installments` (1 a 12, padrão `1`), `threeDSecureSession`, `ipAddress`, `location` e `softDescriptor`, como em [Pagar fatura](../invoices/pay).
</ParamField>

<ParamField body="paymentMethod" type="object">
  Cartão a guardar para a cobrança depois do teste, quando nada é cobrado hoje: `{ type: "card", card }`, com `card` o UUID de um cartão tokenizado. Obrigatório com `paymentMethodCollection: "always"`; opcional com `if_required`. Não pode vir junto de `charge`.
</ParamField>

## Erros

| Status | Código | Quando |
| ------ | ------ | ------ |
| `401` | n/a | Do navegador: `clientSecret` ausente, errado ou de outra sessão |
| `404` | `CHECKOUT_SESSION_NOT_FOUND` | Do servidor: a sessão não existe ou é de outra conta |
| `404` | `CUSTOMER_NOT_FOUND` | O UUID de `customer` não existe na conta |
| `409` | `CHECKOUT_SESSION_NOT_OPEN` | A sessão já está `complete` ou `expired` |
| `410` | `CHECKOUT_SESSION_EXPIRED` | A sessão passou do `expiresAt` |
| `400` | `CHECKOUT_SESSION_CUSTOMER_DATA_REQUIRED` | Do navegador: `customer` veio como UUID; envie os dados |
| `409` | `CHECKOUT_SESSION_CUSTOMER_MISMATCH` | A sessão já pertence a outro cliente, ou o `document` enviado não é o do cliente da sessão |
| `400` | `CHECKOUT_SESSION_PAYER_DOCUMENT_REQUIRED` | A sessão não tem cliente, ou o cliente não tem documento, e o `document` não veio |
| `400` | `CHECKOUT_SESSION_CHARGE_REQUIRED` | Há valor a pagar hoje e `charge` não veio |
| `400` | `CHECKOUT_SESSION_NOTHING_TO_CHARGE` | Nada a pagar hoje (teste) e `charge` veio: envie `paymentMethod` |
| `400` | `CHECKOUT_SESSION_PAYMENT_METHOD_REQUIRED` | Teste com `paymentMethodCollection: "always"` e sem `paymentMethod` |
| `400` | `CHECKOUT_SESSION_PAYMENT_METHOD_NOT_ALLOWED` | O método não está em `paymentMethods` da sessão |
| `400` | `CHECKOUT_SESSION_BUMP_INVALID` | Um `bumps[]` não é da sessão, ou se repete |
| `422` | `VALIDATION_FAILED` | `charge` e `paymentMethod` juntos, `customer` com documento inválido etc. |
| `429` | n/a | Do navegador: mais de 10 confirmações por minuto por sessão e IP |

Os erros do pagamento em si (cartão inexistente ou de outro cliente, 3DS inválido, falha de cobrança) seguem [Pagar fatura](../invoices/pay).
